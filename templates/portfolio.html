02GT Movies Store

GT Movies Store is a Django app for a movie storefront. Anyone can browse the catalog, search it, and read reviews. Once you have an account you can write reviews, add movies to a cart, and check out into an order history.

How it's put together

It's four Django apps instead of one. home has the landing and about pages, movies has the catalog and reviews, cart has the cart and checkout, and accounts handles signup, login, and order history on top of Django's built in User.

There are four models. Movie has a name, price, description, and image. Review points at both a movie and a user, so the app can check if a review is yours before letting you edit it. Checkout creates an Order and one Item per movie. Each item saves the price it was bought at instead of reading it off the movie, so changing a price later doesn't change old orders.

The cart is kept in the session instead of the database, so you can add movies before making an account. Only checkout requires being logged in.

Screens

Screen Route What it does
Home / Landing page with the store branding and a way into the catalog.
About /about Static page describing the store.
Movie list /movies/ Lists every movie, and filters on a case insensitive name match when you search.
Movie detail /movies/<id>/ Shows one movie's image, description, and price, along with its reviews and the add to cart form.
Sign up /accounts/signup Creates an account using Django's UserCreationForm, restyled to match the rest of the site.
Login and logout /accounts/login/ Authenticates against Django's backend, with one generic error message when it fails.
Cart /cart/ Lists what's in the session cart with a running total and a button to empty it.
Purchase confirmation /cart/purchase/ Saves the order, clears the cart so a refresh can't order twice, and shows the order id.
Order history /accounts/orders/ Lists the logged in user's past orders.
Reviews /movies/<id>/review/... Lets a logged in user post a review, and edit or delete their own.
Report review /movies/<id>/review/<id>/report/ Lets a logged in user take down a review they think is inappropriate.
Admin /admin/ Django admin for managing the catalog, including poster uploads.

Every page extends one base.html with the navbar and footer in it. The navbar changes depending on whether you're logged in, swapping Login and Sign Up for Orders and a logout link with your username on it. Layout is Bootstrap 5 with a small stylesheet on top.

03Process

I did one app at a time instead of building everything at once. For each user story I added the model, the url, the view, and the template, then checked it in the browser before moving on.

The order was based on what needed what. home first to get a page rendering, then movies since everything else refers to a movie, then accounts because reviews and orders need a user, and cart last. Building accounts before reviews was useful because a review needs an author before you can check who is allowed to edit it.

For questions I mostly used the Django docs, especially the pages on sessions and the auth decorators. When there were a few ways to do something I went with whatever kept logic out of the templates, which is why the cart total is a helper function and the quantity lookup is a template filter. For bugs I read the traceback and used the admin to see what was in the database.

Most of the bugs I hit were in the cases around a feature rather than the feature itself, like empty reviews, refreshing the confirmation page, or trying to edit someone else's review. The login and ownership checks came out of testing those.
